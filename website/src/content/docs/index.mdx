## Install

```sh
gleam add slate
```

slate targets Erlang, where DETS ships with OTP. There is no database service or JavaScript-target dependency to add.

## What it looks like

Open a table, insert, look up. Every value passes through the decoders you choose, so what comes off disk is typed — not dynamic data you have to trust.

```gleam
import gleam/dynamic/decode
import gleam/result
import slate/set

pub fn main() {
  use users <- set.with_table(
    "data/users.dets",
    key_decoder: decode.string,
    value_decoder: decode.int,
  )
  use Nil <- result.try(
    set.insert(users, "alice", 42),
  )
  set.lookup(users, key: "alice")
}
// Ok(42), and the table is closed
```

`with_table` closes short-lived tables before returning, including when an operation returns an error. Values persist across node restarts; after an abrupt process termination, DETS may repair the file when it next opens. See [Safe Resource Management](/advanced/with-table/) for long-lived tables and repair details.

## When to use DETS

| Approach | Complexity | Persistence | Query capability |
| --------------- | -------- | ----------- | ------------------------------ |
| JSON file | Low | Yes | None |
| **DETS** | **Low** | **Yes** | **Key lookup, fold** |
| SQLite/Postgres | High | Yes | Full SQL |
| Mnesia | High | Yes | Transactions, distribution |

If a config file is too little and a database is too much, DETS is the middle layer you already have. It has real limits — 2 GB per table, disk I/O on every operation — and they are documented plainly in [Limitations](/advanced/limitations/).
