## What it looks like

Open a table, insert, look up. Every value passes through the decoders you choose, so what comes off disk is typed — not dynamic data you have to trust.

```gleam
import gleam/dynamic/decode
import slate/set

pub fn main() {
  // `let assert` unwraps the Ok, crashing on Error — fine for a demo
  let assert Ok(users) = set.open("data/users.dets",
    key_decoder: decode.string, value_decoder: decode.int)

  let assert Ok(Nil) = set.insert(users, "alice", 42)
  let assert Ok(age) = set.lookup(users, key: "alice")
  // age == 42

  let assert Ok(Nil) = set.close(users)
}
```

Tables survive process crashes and node restarts. DETS is part of OTP, so there is nothing else to install, run, or operate.

## When to use DETS

| Approach | Complexity | Persistence | Query capability |
| --------------- | -------- | ----------- | ------------------------------ |
| JSON file | Low | Yes | None |
| **DETS** | **Low** | **Yes** | **Key lookup, fold** |
| SQLite/Postgres | High | Yes | Full SQL |
| Mnesia | High | Yes | Transactions, distribution |

If a config file is too little and a database is too much, DETS is the middle layer you already have. It has real limits — 2 GB per table, disk I/O on every operation — and they are documented plainly in [Limitations](/advanced/limitations/).

## Install

```sh
gleam add slate
```

Erlang target only — DETS is a BEAM feature, with no JavaScript target support. slate is 1.0: the public API is stable under [semver guarantees](/advanced/stability/), and the [Quick Start](/quick-start/) has you reading and writing a table in about two minutes.
